## 1. Multiplayer game netcode (Tribes, Quake 3, Source, Unreal, Halo/Overwatch/Rocket League)

### Takeaway
Games solved MinBand's exact problem in 1999–2001: a server keeps a per-client "ghost" of every replicated object, scores each ghost by priority × time-since-last-update, fills a fixed-size packet in priority order, and on packet loss re-marks the *state* as dirty rather than retransmitting the packet. Delta-against-last-acknowledged-snapshot (Quake 3/Source) and keyframe fallback when the ack is too old are the standard repair pattern. Correction "popping" and cheating were the problems; smoothing-over-N-frames with a snap threshold, server authority and lag compensation were the fixes.

### Cited Findings
- [U] **Tribes networking model** (M. Frohnmayer & T. Gift, "The TRIBES Engine Networking Model", GDC 2001; canonical PDF: https://www.gamedevs.org/uploads/tribes-networking-model.pdf — blocked this session). Layers: platform packet module → connection manager (the *notify protocol*: unreliable sequenced packets carrying an ack bitfield so the sender learns per-packet delivery/loss) → stream manager (per-connection bandwidth/packet-rate budget) → event manager (guaranteed-ordered / guaranteed / unguaranteed events) → **ghost manager** (objects "in scope" for a client get a ghost; each ghost carries an *update mask* of dirty state bits and a *priority*; each packet, ghosts are sorted by priority accumulated with time since last update and written until the packet budget is used; when the notify protocol reports a packet lost, the dirty bits sent in it are OR'd back into the mask so the *current* state is resent, not the old packet). The paper's stated design target is 28.8 kbit/s modems and the engine shipped 128-player servers (Tribes 2). — Unverified; writer should confirm the 28.8 kbit/s and 128-player figures from the PDF.
- [U] **Quake 3** (id Software, 1999; analysis by F. Sanglard, "Quake 3 Source Code Review: Network Model", https://fabiensanglard.net/quake3/network.php — blocked). Server tick `sv_fps` = 20 Hz; each client gets a **snapshot** delta-compressed against the **last snapshot that client acknowledged**; the server keeps a ring of the last **32** snapshots (`PACKET_BACKUP 32`); if the acked snapshot is older than the ring, a **full (non-delta) snapshot** is sent. There is no retransmission: loss is repaired implicitly because the next snapshot is delta'd from an older acked baseline. Entity fields are written with per-field "changed" bits from a `netField` table and Huffman-coded. Client interpolates between snapshots (and `cl_timenudge`/extrapolation are limited). — Unverified this session; high confidence on 20 Hz / 32-deep ring / full-snapshot fallback.
- [U] **Source engine** (Valve Developer Community, "Source Multiplayer Networking", https://developer.valvesoftware.com/wiki/Source_Multiplayer_Networking — blocked). Default server tick 66 Hz (CS:S) / 64 (CS:GO); `cl_updaterate` 20 (max 66); client renders ~100 ms in the past (`cl_interp` = `cl_interp_ratio`/`cl_updaterate` = 2/20); **extrapolation is capped at 0.25 s** (`cl_extrapolate_amount 0.25`) — after that the entity freezes rather than keeps flying; lag compensation up to 1 s (`sv_maxunlag 1.0`); delta compression against the last acked tick with full-update fallback. — Unverified this session; high confidence.
- [U] **Unreal Engine replication** (Epic docs, "Actor Relevancy and Priority" — blocked). `NetPriority` default 1.0 for Actors, 3.0 for Pawns/PlayerControllers; priority is multiplied by time since the actor was last replicated (starvation prevention); `NetUpdateFrequency` default 100 Hz, `MinNetUpdateFrequency` 2 Hz (a "heartbeat floor" for unchanged actors); relevancy via `NetCullDistanceSquared` default 225,000,000 cm² (= 150 m). — Unverified this session; high confidence on 1.0/3.0/100/2/150 m.
- [U] **Gaffer on Games, "Snapshot Compression"** (G. Fiedler, 2015, https://gafferongames.com/post/snapshot_compression/ — blocked). 900 physics cubes at 60 Hz: naive floats ≈ 17 Mbit/s; after quantizing position and "smallest-three" quaternion orientation (9–10 bits per component) and delta-encoding against the last *acked* snapshot with per-object "not changed" bits, final ≈ 256 kbit/s. The lesson Fiedler draws: delta against what the receiver is *known* to have (acked), never against what was merely sent. — Unverified; figures approximate.
- [U] **Halo: Reach** (D. Aldridge, "I Shot You First: Networking the Gameplay of Halo: Reach", GDC 2011): per-connection bandwidth budget, prioritized object replication (priority a function of distance/screen relevance and age), separate reliable "events" vs eventually-consistent "state". **Overwatch** (T. Ford, "Overwatch Gameplay Architecture and Netcode", GDC 2017): fixed 62.5 Hz simulation, client prediction with server reconciliation, update rate raised to ~60 Hz in 2016 to cut correction visibility. **Rocket League** (J. Cone, "It IS Rocket Science!", GDC 2018): full deterministic physics re-simulation on the client, server snapshots; small errors are blended over several frames, large errors snap. — Talk titles are correct; specific numbers unverified.
- [U] **Known failure modes and fixes.** Mispredictions → visible correction ("rubber-banding"); fix = smooth small corrections over N frames, hard snap above a threshold (Source `cl_smooth`/`cl_smoothtime 0.1`). Client authority → cheating; fix = server authority + lag compensation ("I shot you first"), which creates "peeker's advantage" as the accepted trade-off. Extrapolation beyond a fraction of a second creates confident-but-wrong positions; fix = extrapolation caps (Source 0.25 s) and interpolation with a deliberate delay.

### Inferences
- The Tribes ghost manager is literally MinBand's architecture (per-client ghost + dirty mask + priority × age + budget-filled packets + loss repaired by re-dirtying state). MinBand's "no retransmission queue, resend current state" is the notify-protocol rule.
- All of these engines keep a **periodic forced update** for unchanged objects (Unreal 2 Hz floor, Quake full snapshots when acks lapse, Source full updates) — the same role as MinBand's 2 s keyframe.
- The extrapolation cap (0.25 s in Source) is the games' answer to "false confidence from smooth extrapolation": past the cap, freeze or fade rather than keep predicting.

### Gaps
- Could not fetch the Tribes PDF to confirm the exact packet budget per client (I recall a per-connection fixed packet size and rate, but not the numbers) or the 28.8 kbit/s/128-player wording.
- Could not confirm Quake 3's default `rate` (bytes/s per client) or Overwatch/Rocket League numeric update rates.

## 2. Automotive V2X (ETSI CAM, SAE J2735/J2945 BSM, DCC, security overhead)

### Takeaway
ETSI's CAM rule is the cleanest published "send on change, bounded by min/max interval" policy: a vehicle sends when heading changed ≥ 4°, position > 4 m or speed > 0.5 m/s since the last message, never faster than 100 ms, never slower than 1 s, and keeps the triggered rate for 3 messages before relaxing. SAE J2945/1 goes one step further toward MinBand: it triggers on *tracking error* between the receiver's dead-reckoned view and truth. Both accept that security (signature + certificate) can exceed the payload, and both have an explicit congestion controller that widens intervals under channel load.

### Cited Findings
- [U] **ETSI EN 302 637-2 (CAM) generation rules** (V1.3.2 / V1.4.1, clause 6.1.3; canonical PDF https://www.etsi.org/deliver/etsi_en/302600_302699/30263702/01.04.01_60/en_30263702v010401p.pdf — blocked): `T_GenCamMin` = 100 ms, `T_GenCamMax` = 1000 ms; a CAM is generated when, since the last CAM, |Δheading| ≥ 4°, or |Δposition| > 4 m, or |Δspeed| > 0.5 m/s, provided ≥ `T_GenCam_DCC` has elapsed; after a dynamics-triggered CAM the station keeps generating at that interval for `N_GenCam` consecutive CAMs (default/max 3) before re-evaluating; otherwise a CAM is generated every `T_GenCamMax`. The check runs every `T_CheckCamGen` ≤ `T_GenCamMin`. The **low-frequency container** (vehicle role, lights, path history) is included only every 500 ms. `T_GenCam_DCC` is set by the DCC entity within [100 ms, 1000 ms]. — High confidence; unverified this session.
- [V] **ETSI ITS Common Data Dictionary & CAM ASN.1 are shipped in `pycrate`** (pycrate 0.8.1, files `pycrate_asn1dir/ITS_CAM_2.py`, `ITS_r1318.py`, `ITS_DENM_3.py`, `ITS_VAM_3.py`, `ITS_IEEE1609_2.py`; https://pypi.org/project/pycrate/0.8.1/). I could not extract the per-type ranges from the compiled form in the time available (see Gaps), but the module list confirms the message family (CAM, DENM, VAM, IEEE 1609.2 security) and that security (1609.2) is defined alongside the payload.
- [U] **CAM/CDD quantization** (ETSI TS 102 894-2 CDD): latitude/longitude in 0.1 µ° (`Latitude` −900,000,000..900,000,001 with 900,000,001 = unavailable), heading in 0.1° (`HeadingValue` 0..3601, 3601 = unavailable), speed in 0.01 m/s (`SpeedValue` 0..16383, 16383 = unavailable), `GenerationDeltaTime` = TimestampIts mod 65536 ms (16 bits), path history as `DeltaLatitude`/`DeltaLongitude` (0.1 µ°) and `PathDeltaTime` (10 ms units) relative to the previous point; every field carries an explicit **"unavailable" sentinel** and a paired **confidence** field (`HeadingConfidence` 0.1°, `SpeedConfidence` 0.01 m/s, `PosConfidenceEllipse` semi-axes in cm). — Unverified this session; high confidence on units.
- [U] **SAE J2735 BSM / J2945/1**: BSM Part I "core data" is ~39 bytes (msgCnt, 4-byte temporary ID, secMark ms, lat/long 1/10 µ°, elevation 0.1 m, positional accuracy, transmission, speed 0.02 m/s, heading 0.0125°, steering angle, 4-axis acceleration, brake status, size). Nominal rate 10 Hz (100 ms). **J2945/1 congestion control** scales the inter-transmit time between 100 ms and a max of **600 ms** as a function of vehicle density (vehicles within 100 m) and channel busy percentage, and additionally sends *sooner* when the **position tracking error** — the difference between the vehicle's true position and the position a receiver would extrapolate from the last BSM — exceeds a threshold on the order of 0.2–0.5 m. Temporary IDs rotate roughly every 5 min for privacy. — Unverified; the tracking-error mechanism is real (it is what makes J2945/1 "dead-reckoning aware"), exact thresholds should be checked.
- [U] **ETSI TS 102 687 DCC** (https://www.etsi.org/deliver/etsi_ts/102600_102699/102687/01.02.01_60/ts_102687v010201p.pdf — blocked): *reactive* approach uses channel-busy-ratio (CBR) state machine Relaxed / Active / Restrictive with per-state minimum packet intervals (`T_off`) and a per-station duty-cycle cap; *adaptive* approach (LIMERIC) converges all stations to a target CBR ≈ 0.68 with gain parameters α ≈ 0.016, β ≈ 0.0012, per-step change bounded by δ_max ≈ 0.03 and δ_min ≈ 0.0006. — Unverified; medium confidence on constants.
- [U] **Security overhead** (IEEE 1609.2 / ETSI TS 103 097): every CAM is signed (ECDSA P-256, 64-byte signature); the full authorization certificate (~100–150 bytes) is attached at least once per second or when a new neighbour is heard/requests it, otherwise an 8-byte certificate digest; so a ~200-byte CAM can carry 70–220 bytes of security. The field accepted this because unauthenticated V2X was judged unusable for safety. — Unverified; structure is correct, byte counts approximate.

### Inferences
- The 4 m / 4° / 0.5 m/s rule is a *sender-dynamics* threshold, not a prediction-error threshold; J2945/1's tracking-error rule is the closer precedent to MinBand's ghost error. MinBand's 0.15 m / 0.3 m/s is ~25× tighter in position than CAM, consistent with a camera-tracked-entity use case rather than self-reports.
- `N_GenCam = 3` ("hold the triggered rate for three messages") is a cheap anti-flapping rule MinBand could copy.
- Every CDD field carrying a sentinel + confidence is a precedent for sending *uncertainty* with each delta (MinBand's confidence field).

### Gaps
- Could not read the ETSI or SAE texts; all numbers are recollection. Could not extract the CDD ranges from pycrate's compiled modules (naming differs from the raw ASN.1).
- No verified byte size for a typical CAM with security.

## 3. Maritime AIS (ITU-R M.1371)

### Takeaway
AIS is a 1990s "state broadcast on a shared slotted channel": a 168-bit position report whose interval is a function of the sender's own dynamics (2 s when fast or turning, 3 min at anchor), a self-organizing TDMA that announces future slot use, and no authentication at all — which produced the spoofing / ghost-ship literature and the practical fix of plausibility filtering and cross-sensor confirmation.

### Cited Findings
- [V] **Class A position report (messages 1/2/3) is exactly 168 bits**, field by field: msg type 6, repeat 2, MMSI 30, nav status 4, rate of turn 8, SOG 10, position accuracy 1, longitude 28, latitude 27, COG 12, true heading 9, UTC second 6, manoeuvre 2, spare 3, RAIM 1, communication state 19 (sum 168) — `pyais` 3.3.0, `pyais/messages.py` `MessageType1` (https://pypi.org/project/pyais/3.3.0/).
- [V] **Quantization:** SOG in 0.1 kn (`from_speed = v*10`), lat/lon in 1/10,000 arc-minute (`v*600000`, i.e. ≈ 0.185 m at the equator), COG 0.1°, heading 1°; rate of turn is sent as `4.733·sqrt(ROT°/min)` in a signed 8-bit field, with ±127 meaning "turning faster than 5°/30 s, no turn indicator" and −128 "not available" — `pyais/messages.py` (`to_turn`/`from_turn`, `from_lat_lon`) and `pyais/constants.py` `TurnRate`.
- [V] **Class B report (message 18) is also 168 bits** with the same position/speed/course fields and 1-bit capability flags (CS unit, display, DSC, band, msg22, assigned, RAIM) — `MessageType18`. **Long-range (satellite) message 27 is 96 bits**: lat/lon at 1/10 arc-minute (≈ 185 m), speed 6 bits (1 kn), course 9 bits (1°) — `MessageType27`. I.e. the standard already defines a *coarser* encoding for the low-capacity path.
- [V] **SOTDMA communication state (19 bits)**: sync state 2 bits (UTC direct / UTC indirect / base-station / other-station), **slot time-out 3 bits** ("frames remaining until a new slot is selected; 0 = last transmission in this slot, 1–7 = frames left"), sub-message 14 bits whose meaning depends on time-out: received-station count (0–16,383) when 3/5/7, slot number (0–2,249) when 2/4/6, UTC hour/minute when 1, next-frame slot offset when 0. **ITDMA**: slot increment 13 bits, number of slots 3 bits (1–5), keep flag 1 bit — `pyais/util.py` `get_sotdma_comm_state`, `get_itdma_comm_state` (docstrings cite ITU-R M.1371-1 and USCG NAVCEN).
- [V] Navigation status enum values (0 under way using engine, 1 at anchor, 5 moored, 8 under way sailing, 14 AIS-SART active, 15 undefined) — `pyais/constants.py` `NavigationStatus`. (These drive the reporting-interval table below.)
- [U] **Reporting intervals (M.1371 Table 1, Class A):** at anchor/moored and ≤ 3 kn: 3 min; at anchor/moored and > 3 kn: 10 s; 0–14 kn: 10 s; 0–14 kn and changing course: 3⅓ s; 14–23 kn: 6 s; 14–23 kn changing course: 2 s; > 23 kn: 2 s (also when changing course). Static/voyage data (message 5, 424 bits, 2 slots) every 6 min. **Class B "CS":** < 2 kn: 3 min; 2–14 kn: 30 s; 14–23 kn: 15 s; > 23 kn: 5 s. Base stations: 10 s. — Unverified this session; high confidence.
- [U] **Channel/slot numbers:** 9,600 bit/s GMSK; 2,250 slots per 60 s frame per channel (26.67 ms/slot, 256 bits/slot: 24-bit training + 8 start flag + 168 data + 16 CRC + 8 end flag + 24 buffer); two channels (161.975 / 162.025 MHz) → 4,500 slots/min; stations reserve slots 3–7 frames ahead (the slot time-out field) and announce the next slot so neighbours avoid it; "received stations" tells others the load. — Unverified; high confidence on 2,250/26.67 ms/256.
- [U] **UTC-second field special values** (M.1371 message 1 "time stamp"): 60 = not available, 61 = positioning system in manual input mode, **62 = electronic position fixing system in estimated (dead reckoning) mode**, 63 = inoperative. I.e. the protocol flags when the reported position is itself dead-reckoned. — Unverified; medium-high confidence.
- [U] **Spoofing / ghost ships:** Balduzzi, Pasta & Wilhoit, "A Security Evaluation of AIS" (ACSAC 2014, Trend Micro) demonstrated software-defined-radio AIS spoofing (fake vessels, fake CPA collision alerts, man-overboard, SAR aircraft), **slot starvation / frequency-hopping DoS**, and availability attacks, all because M.1371 has no authentication or integrity beyond a CRC. GPS-level spoofing moved ships' AIS tracks to inland airports in the Black Sea (June 2017, reported by Maritime Executive/C4ADS) and produced "crop-circle" tracks off Shanghai (2019, MIT Technology Review/SkyTruth). Mitigations in practice: receiver-side plausibility filters (max speed, max turn, position jumps), cross-checking with radar/satellite imagery, IMO guidance that AIS must not be the sole collision-avoidance input, and proposals for authenticated VDES/ASM. — Unverified; the ACSAC 2014 paper is real.

### Inferences
- AIS's "interval is a function of own dynamics" is a sender-side proxy for prediction error: faster/turning ⇒ a linear ghost diverges faster ⇒ report more often. MinBand's explicit ghost comparison is the principled version.
- Message 27 shows the field already accepted *different quantization per link class* (0.185 m vs 185 m). MinBand's budget controller widening thresholds is the continuous analogue.
- The slot time-out / "I will transmit next at slot N" announcement is a precedent for telling the receiver *when to expect the next update*, which turns silence into information (see §10).
- The 62 = "position is dead-reckoned" flag is the cheapest known integrity measure: one 6-bit sentinel that says "coasting".

### Gaps
- Table 1 intervals and the 256-bit slot breakdown could not be verified against M.1371 text this session.
- No verified figure for AIS slot collisions/loss in congested ports (literature exists, e.g. for Singapore/Rotterdam, not reachable).

## 4. Aviation (ADS-B, Mode S, radar/ATC track coasting)

### Takeaway
ADS-B packs lat/lon into 17 bits each by *Compact Position Reporting*, which is only decodable because the receiver is assumed to hold recent state (an even/odd pair ≤ 10 s apart, or a reference within 180 NM) — a receiver-state-dependent encoding like MinBand's deltas. Every position carries self-declared integrity/accuracy categories (NIC/NACp/SIL) but no authentication, and the field's answer to spoofing was cross-sensor plausibility (MLAT, radar, motion consistency), not crypto. Surveillance trackers display coasted tracks explicitly and drop them after a fixed age.

### Cited Findings
- [V] **1090ES ADS-B**: DF17/18 messages are 112 bits with a 56-bit ME payload; a 5-bit typecode (payload bits 0–4) selects the content: TC 1–4 identification, TC 5–8 surface position, **TC 9–18 airborne position (barometric)**, **TC 19 airborne velocity**, TC 20–22 airborne position (GNSS altitude), TC 28/29/31 status — `pyModeS` 3.6.0, `src/pyModeS/decoder/adsb.py` and `README.md` (https://pypi.org/project/pyModeS/3.6.0/).
- [V] **CPR encoding**: 17-bit lat and lon fields (denominator 2^17 = 131,072), `NZ = 15` latitude zones ("fixed by DO-260B"), 60 even / 59 odd zones; a global decode needs an even and an odd frame and, per the implementation's docstring, "the pair must be ≤ 10 seconds apart — ADS-B airborne position messages broadcast at ~2 Hz, and a pair older than that may straddle a cprNL boundary"; the decoder adds a `cprNL` equality sanity check. Local decode against a known reference requires the reference within **180 NM** (airborne, DO-260B §A.1.7.5) or **45 NM** (surface) — `src/pyModeS/position/_cpr.py`. (Derived: 6° zone / 131,072 ≈ 4.6 × 10⁻⁵ ° ≈ 5 m latitude resolution.)
- [V] **Vertical rate** is 9 bits at (value − 1) × 64 ft/min with sign and source bits (GNSS vs barometric) — `decoder/bds/bds09.py`. Surface movement uses non-uniform speed bins — `bds06.py`.
- [V] **Self-declared integrity/accuracy tables** carried in the message: NUCp → horizontal protection limit (NUCp 9: HPL < 7.5 m; 8: 25 m; 7: 185 m; … 1: 37,040 m); NIC → containment radius Rc (NIC 11: 7.5 m; 10: 25 m; 9: 75 m; 8: 185 m; 7: 370 m; 6: 926/1,111 m; 5: 1,852 m; …); NACp → EPU (11: 3 m; 10: 10 m; 9: 30 m; 8: 93 m; 7: 185 m; 6: 556 m; …); NACv → velocity error (4: 0.3 m/s; 3: 1 m/s; 2: 3 m/s; 1: 10 m/s); **SIL → probability of exceeding Rc (3: 1e-7; 2: 1e-5; 1: 1e-3)** — `src/pyModeS/_uncertainty.py`.
- [V] **Staleness conventions in a production decoder**: CPR pair window 10 s; last accepted position usable as local reference for 30 s; per-aircraft state evicted after 300 s without messages; a motion-consistency check (max 1,500 kt, 2 km margin, 5-position history) rejects "phantom" positions, and rejected candidates still enter the history so a track anchored on phantoms can recover — `src/pyModeS/_pipe.py`.
- [U] **Transmit rates (RTCA DO-260B §2.2.3.3)**: airborne position every 0.4–0.6 s (nominal 2 Hz), velocity 2 Hz, identification every 5 s airborne (10 s on surface), surface position 2 Hz moving / every 5 s stationary; total ≈ 6 messages/s per aircraft. — Unverified; high confidence on 2 Hz / 5 s.
- [U] **No authentication**: Costin & Francillon, "Ghost in the Air(Traffic)" (Black Hat 2012) and Strohmeier, Lenders & Martinovic, "On the Security of the Automatic Dependent Surveillance-Broadcast Protocol" (IEEE Communications Surveys & Tutorials, 2015) catalogue ghost-aircraft injection, message deletion and jamming on 1090ES; proposed mitigations are **multilateration (TDOA) consistency**, Kalman/physical plausibility checks, fusion with SSR radar, and fingerprinting — not crypto, because the message format is frozen. — Unverified; papers are real.
- [U] **Track coasting in ATC**: Eurocontrol ASTERIX CAT062 (system tracks) item I062/080 "Track Status" has a **CST = coasted** bit ("age of the last received track update is higher than a system-dependent threshold"), **CNF = tentative vs confirmed**, TSE/TSB (track service end/begin), SIM, and CAT062 I062/290 "System Track Update Ages" carries per-sensor ages in 0.25 s units up to 63.75 s; CAT048 I048/170 has CNF (confirmed/tentative), TRE (last report), **GHO (ghost track from reflection)**, DOU (doubtful), MAH (manoeuvre). Trackers coast for a few missed scans (typically 3–6 at 4–12 s rotation) before termination, and HMIs draw coasted tracks with a distinct symbol. — Unverified; high confidence on the ASTERIX bit names, low on the exact scan counts.

### Inferences
- CPR is a worked example of a **receiver-state-dependent encoding**: 34 bits of position are only meaningful if the receiver has a recent frame or a reference; the 10 s / 180 NM rules are explicit statements of how stale the receiver's state may be. MinBand's deltas have the same property and should carry an equally explicit validity window.
- NIC/NACp/SIL show that broadcasting *claimed* uncertainty per message is standard practice and cheap (a few bits), but that claimed integrity is not authenticity — the two must be separated in MinBand's twin (confidence ≠ trust).
- The ADS-B decoder's eviction (300 s) and reference (30 s) windows, plus explicit "coasted" display bits in ASTERIX, are the mature answer to "how to show stale tracks": mark, then drop, never silently extrapolate.

### Gaps
- Exact ATC coast/drop scan counts (FAA STARS/ERAM, Eurocontrol ARTAS) and TCAS track-drop timing not verifiable here.
- DO-260B transmit-rate wording not verified.

## 5. Naval tactical data links (Link 11/16/22, R2, track quality, CTP)

### Takeaway
Tactical data links solved "many sensors, one target" with explicit rules: one unit holds **Reporting Responsibility (R2)** for each track and only it transmits updates; a 4-bit **Track Quality** number decides who should hold R2 and how often to report; **track-number blocks** are pre-allocated per unit so IDs never collide; and dual designation (two track numbers for one object) is handled by a dedicated track-management message class. The bit budgets were brutal (Link 11 at 1,364/2,250 bit/s shared by the whole net).

### Cited Findings
- [U] **Link 11 (TADIL-A)**: HF/UHF net with a Net Control Station polling each Participating Unit in turn ("roll call"); data rates **1,364 bit/s ("slow") or 2,250 bit/s ("fast")**; M-series messages built from 30-bit words (24 data + 6 EDAC); net-cycle time grows with the number of participants (seconds to tens of seconds), so a track's update interval is set by the net cycle, not the target's dynamics. — Unverified; high confidence on 1,364/2,250.
- [U] **Link 16 (TADIL-J, MIL-STD-6016 / STANAG 5516)**: TDMA with **128 time slots per second (7.8125 ms each)**, 1,536 slots per 12 s frame, 98,304 slots per 12.8 min epoch; J-series messages of 70-bit words, 3 words per message; a slot carries 3/6/12 words (standard / packed-2 / packed-4) giving nominal throughputs of 28.8 / 57.6 / 115.2 kbit/s net-wide; **J2.x PPLI** (own position) and **J3.x surveillance tracks** (J3.2 air, J3.3 surface, J3.4 subsurface, J3.5 land point, J3.6 space); **J7.x track management** (drop track, change track number, R2 shift, correlation). — Unverified; high confidence on slot timing and message families.
- [U] **Track Quality (TQ)**: a 4-bit (0–15) field in J3.x track messages expressing the reporting unit's positional confidence in the track (derived from the 95 % error radius / time since last sensor update; 15 = best, 0 = no confidence); **TQ decays with track age** when the sensor stops updating, which automatically lowers the unit's claim on R2. — Unverified; medium-high confidence.
- [U] **Reporting Responsibility (R2) rule**: exactly one JU reports a given track; another JU may assume R2 if its TQ exceeds the current reporter's TQ by a margin (I recall "by 2 or more") for a sustained period; R2 shifts are signalled via J7.0; units not holding R2 still correlate their local sensor track to the reported track number and suppress their own report. **Dual designation** (two track numbers on one object) arises when correlation fails (sensor error, long gaps, manoeuvres); it is resolved by correlation/decorrelation messages and by assigning **track-number blocks per unit** so numbers never collide across reporters. Update periods are tied to track type/TQ (air tracks on the order of 12 s or faster, surface slower). — Unverified; the R2 margin and update periods need checking against MIL-STD-6016/ADatP-33.
- [U] **Link 22 (NILE)**: HF (1.5–4 kbit/s range) and UHF, dynamic TDMA with late net entry and priority-based slot reallocation; F-series/FJ messages map J-series content so a mixed Link 16/22 picture stays one track namespace. — Unverified; low-medium confidence on rates.
- [U] **Cooperative Engagement Capability (CEC)** is the counter-example: instead of reporting tracks, ships share raw **sensor measurements** to build one composite track with fire-control quality, which required a dedicated high-capacity directional data link (DDS) because measurements cost far more bandwidth than tracks. — Unverified; high confidence on the concept.

### Inferences
- R2 + TQ is the field's solution to MinBand's multi-sensor fusion over a thin link: don't have every sensor send every entity; elect one reporter per entity by quality, let quality decay with age, and reserve ID ranges per sensor so merges never collide. The "TQ margin before R2 shift" is a hysteresis rule that prevents reporter flapping.
- Track-number blocks per unit are the direct precedent for namespacing entity IDs per edge device before fusion.
- CEC vs Link 16 is the quantified trade: tracks (state) fit in kbit/s; measurements (observations) need orders of magnitude more. MinBand sits firmly on the track side.

### Gaps
- Exact R2 margin, TQ computation table and J3.2 update periods could not be verified (MIL-STD-6016 is restricted; public summaries exist in the Northrop Grumman "Understanding Link-16" guidebook and USN NTTP but were unreachable).

## 6. Space and deep-space links (Voyager/Mars rates, CCSDS, DTN)

### Takeaway
Deep-space practice gave up on end-to-end retransmission as the primary repair tool decades ago: frames carry counters so gaps are *detected*, reliability is pushed to hop-by-hop convergence layers or to selective "red/green" reliability, and the Bundle Protocol's core design is **store-and-forward with a lifetime after which stale data is dropped rather than delivered late**. BPv7 even removed custody transfer from the core. Spacecraft telemetry is organized as prioritized packets with "update on change" channels.

### Cited Findings
- [V] **Bundle Protocol v7 (RFC 9171) structure**, as implemented in `py-dtn7` 0.3.0b1 (`py_dtn7/bundle.py`; https://pypi.org/project/py-dtn7/0.3.0b1/): the primary block is a CBOR array of 8–11 elements (8 if not a fragment and no CRC, 9 with CRC, 10 fragment without CRC, 11 fragment with CRC); CRC types 0 = none, 1 = X-25 (CRC-16), 2 = CRC32C; the primary block carries **creation timestamp and `lifetime` in ms** (this library defaults lifetime to 24 h = 86,400,000 ms); bundle processing-control flags request **status reports for reception, forwarding, delivery and deletion**; a "do not fragment" flag; block flags "replicate in every fragment" and "report if block can't be processed". The README notes the implementation omits fragment and CRC support — i.e. the spec has them.
- [U] **RFC 4838 (DTN architecture, 2007) and RFC 9171 (BPv7, 2022)** (https://www.rfc-editor.org/rfc/rfc4838, https://www.rfc-editor.org/rfc/rfc9171 — blocked): the architecture assumes no end-to-end path at any instant, long/variable delay and asymmetric links; it replaces TCP-style end-to-end ARQ with **store-and-forward over scheduled/opportunistic contacts**, hop-by-hop reliability in convergence layers (TCPCL RFC 9174, LTP RFC 5326), **bundle expiry by lifetime**, and (in v6) **custody transfer** — a node accepting custody takes over retransmission responsibility. **BPv7 removed custody transfer from the base protocol** (moved to the Bundle-in-Bundle Encapsulation extension), concluding that hop-by-hop custody was rarely implementable/useful enough to be mandatory; status reports remained as the feedback primitive. — Unverified this session; high confidence on the custody removal.
- [U] **LTP (RFC 5326)** splits each block into a **"red" part (reliable, acknowledged, retransmitted) and a "green" part (best effort, never retransmitted)**; mission practice puts headers/critical state in red and bulk data in green. — Unverified; high confidence.
- [U] **CCSDS link layers**: TM Space Data Link (CCSDS 132.0-B) and AOS (732.0-B) frames carry virtual-channel and master-channel frame counters so the ground detects gaps but the link layer never retransmits; Proximity-1 (211.x, used on Mars UHF relay) adds go-back-N ARQ; the CCSDS File Delivery Protocol (727.0-B) offers Class 1 (unreliable) and Class 2 (reliable, NAK-based, including *deferred* NAK mode where the receiver reports all gaps at the end of a pass) — the receiver asks for what is missing rather than the sender timing out. — Unverified; high confidence on CFDP classes.
- [U] **Rates**: Voyager 1/2 now downlink at **160 bit/s** (engineering/science) to 70 m DSN antennas, with one-way light time ~22 h (2024); Jupiter encounter rates were up to 115.2 kbit/s. Mars rovers direct-to-Earth X-band ≈ 0.5–32 kbit/s, but ≈ 2 Mbit/s over UHF relay to MRO/Odyssey during ~8 min passes a few times per sol, delivering most of the ~250 Mbit/sol science return. — Unverified; high confidence on 160 bit/s and the relay-vs-direct asymmetry.
- [U] **Event-driven telemetry in flight software**: NASA's F´ (F Prime) framework distinguishes **events** (discrete, always sent) from **telemetry channels** (sampled; a channel can be declared `update on change` so it is only downlinked when its value changes) and groups channels into **packets with fixed downlink rates** (prioritized packet IDs); JPL missions have long used "change-only" channel reporting and *event reports (EVRs)* with severity levels. — Unverified; high confidence that FPP has `update on change`.

### Inferences
- DTN's conclusion maps directly onto MinBand's "no retransmission queue": when links are intermittent, retransmitting *old* data after a blackout is often worse than sending *current* state with an expiry; BPv7's lifetime is the formalization of "a delta older than X is worthless". MinBand's 2 s keyframe is effectively a very short lifetime.
- LTP's red/green split is a precedent for giving *different reliability to different fields* (e.g., class/identity red, position green) within one message.
- The deferred-NAK pattern (receiver lists gaps at end of contact) is a cheap, link-friendly alternative to per-packet acks if MinBand ever adds a back channel.

### Gaps
- RFC texts unverified; Voyager and Mars rates from memory; no verified figure for how many bundles DTN flight experiments (e.g., ISS/DINET 2008) dropped vs delivered.

## 7. Industrial telemetry and SCADA (report-by-exception, DNP3, IEC 61850 GOOSE, OPC UA)

### Takeaway
Industrial protocols have had "report by exception with a deadband, plus a periodic integrity poll to repair drift" since the 1990s. DNP3's unsolicited responses are confirmed-with-retry and buffered with explicit overflow flags; GOOSE answers loss with **state-numbered repetition at geometrically increasing intervals** (an emission policy that is idempotent and needs no acks); OPC UA standardizes deadband types (None/Absolute/Percent), trigger types (Status/StatusValue/StatusValueTimestamp), queueing with discard-oldest, and keep-alive publishes.

### Cited Findings
- [V] **DNP3 deadband rule (opendnp3, bundled in `pydnp3` 0.1.0, `deps/dnp3/cpp/libs/include/opendnp3/app/EventTriggers.h`; https://pypi.org/project/pydnp3/0.1.0/)**: an analog/counter value becomes an *event* iff `|new − old| > deadband` (strict inequality, computed in unsigned arithmetic to avoid overflow). Events are assigned to **event classes 1/2/3** (`PointClass` bitmask: Class0 = static only, Class1/2/3 = event classes) — `opendnp3/app/PointClass.h`.
- [V] **DNP3 outstation defaults (opendnp3 `OutstationParams.h`, `AppConstants.h`)**: `allowUnsolicited = false` (master must enable); `unsolClassMask = None` until enabled; **unsolicited confirm timeout 5,000 ms** and **unsolicited retry timeout 5,000 ms** (`DEFAULT_APP_TIMEOUT`); solicited confirm timeout 5,000 ms; max APDU/fragment size **2,048 bytes**; select-before-operate timeout 10 s; max 16 controls per request. Event storage is a **preallocated per-type buffer** (`EventBufferConfig`: `maxBinaryEvents`, `maxAnalogEvents`, …) that *overflows* when full — "Implementations should configure the buffers to store a reasonable number [of] events given the polling frequency".
- [U] **DNP3 (IEEE 1815) procedure**: outstation sends a NULL unsolicited response at startup; master enables unsolicited per class (FC 20); master runs an **integrity poll** (Class 0 static + Class 1/2/3 events) at startup and periodically (hours) and **event polls** frequently; events carry 48-bit ms timestamps; buffer overflow is signalled by an IIN bit so the master knows it must integrity-poll; application-layer confirms with retries. — Unverified; high confidence.
- [U] **IEC 60870-5-101/104**: cause-of-transmission codes distinguish **spontaneous (COT = 3)** report-by-exception, **cyclic/periodic (COT = 1)**, and **interrogated by general interrogation (COT = 20)** — the general interrogation being the integrity "keyframe". Measurands can be configured with thresholds (deadbands) and smoothing. — Unverified; high confidence.
- [U] **IEC 61850-8-1 GOOSE retransmission ("emission policy")**: on a dataset change the publisher transmits immediately and then **repeats the full state** at increasing intervals (T1, T1, T2, T3, … up to the stable interval T0, e.g. 1 s; vendor sequences like 4, 4, 8, 16, 32 … 1000 ms are common); each message carries **stNum** (incremented on every state change), **sqNum** (incremented per repetition, reset to 0 on change) and **timeAllowedToLive** (typically 2× the next interval) so subscribers detect lost or stale publishers; no acknowledgements at all. Also `test`, `ndsCom` and `confRev` flags. — Unverified; high confidence on structure, vendor-specific numbers.
- [V] **OPC UA Part 4 enums as implemented in `asyncua` 2.1.0** (`asyncua/ua/uaprotocol_auto.py`; https://pypi.org/project/asyncua/2.1.0/): `DeadbandType` {None_ = 0, Absolute = 1, Percent = 2}; `DataChangeTrigger` {Status = 0, StatusValue = 1, StatusValueTimestamp = 2} (docstring cites Part 4 §7.10); `DataChangeFilter` = {Trigger, DeadbandType, DeadbandValue} (§7.22.2); `MonitoringParameters` = {ClientHandle, **SamplingInterval**, Filter, **QueueSize**, **DiscardOldest** = True} (§7.21); `CreateSubscriptionParameters` = {RequestedPublishingInterval, RequestedLifetimeCount, RequestedMaxKeepAliveCount, MaxNotificationsPerPublish, PublishingEnabled, Priority}. The server evaluates absolute deadband as `abs(cur − old) > DeadbandValue` (strict) in `asyncua/server/monitored_item_service.py` (`_is_deadband_exceeded`); this implementation does not implement Percent.
- [U] **OPC UA semantics**: Percent deadband is relative to the variable's EURange; a subscription sends an empty **keep-alive** publish after `MaxKeepAliveCount` publishing intervals with nothing to report, and is torn down after `LifetimeCount` intervals without a client Publish (the spec requires LifetimeCount ≥ 3 × MaxKeepAliveCount). — Unverified; high confidence.

### Inferences
- The DNP3 pattern "events by exception + periodic integrity poll + overflow flag" is the mature form of MinBand's "deltas + 2 s keyframe"; the overflow flag is the missing piece — MinBand's edge could flag "I dropped deltas under budget" so the twin knows a keyframe is needed sooner.
- GOOSE's geometric repetition (fast repeats right after a change, slowing to a heartbeat) is a good precedent for MinBand's repair policy: resend state at short intervals immediately after a change (when loss hurts most), then back off to the keyframe period. stNum/sqNum are the idempotency keys.
- OPC UA's `QueueSize`/`DiscardOldest` is the standardized version of "keep only the newest state when the consumer is slow".

### Gaps
- GOOSE timing constants are vendor-dependent; the standard's T0–T3 text was not verifiable.
- DNP3 primer (dnp.org) and IEC texts were unreachable.

## 8. Wildlife and oceanographic tracking (Argos, satellite tags, GPS collars)

### Takeaway
Animal tags face multi-day blackouts and messages of ≤ 32 bytes, so the field standardized on (a) **on-board summarization** of what happened during the blackout (dive histograms, "broken-stick" compressed profiles) instead of raw samples, (b) **store-and-forward until a pass**, and (c) **receiver-side plausibility filtering and state-space smoothing** of noisy, irregular fixes. Location quality classes are attached to every fix.

### Cited Findings
- [U] **Argos system** (CLS, https://www.argos-system.org — blocked): uplink at 401.65 MHz; message payload up to **31–32 bytes** (Argos-2/3; shorter 4–8-byte messages for Argos-1 platforms); platform repetition period typically **45–200 s** (set per application, e.g. 45–60 s for marine animals that surface briefly); transmissions ≈ 360–920 ms; **Doppler location classes**: 3 (< 250 m), 2 (250–500 m), 1 (500–1,500 m), 0 (> 1,500 m), A/B (fewer messages, no error estimate), Z (invalid); classes 0–3 require ≥ 4 messages in a pass, A needs 3, B 1–2; Argos-3/4 add a downlink and higher rates (up to 4.8 kbit/s). — Unverified; high confidence on classes and the 31/32-byte limit.
- [U] **Satellite tag summarization** (Wildlife Computers SPOT/SPLASH/MiniPAT; SMRU CTD-SRDL): because only a few passes/day succeed, tags transmit **histograms** (time-at-depth, time-at-temperature, dive duration) binned over 6-hour or 24-hour periods, **"broken-stick" compressed dive profiles** (SMRU keeps the 4 inflection points that best approximate a dive), and pop-up archival tags transmit months of light-level geolocation summaries after release; raw archives are only recovered physically. Fastloc-GPS captures a ~10 ms GNSS snapshot and defers position solving to the ground to keep on-animal power/bytes tiny. — Unverified; high confidence on the broken-stick and histogram practice.
- [U] **GPS collars (Lotek, Vectronic, Telonics)**: fixes on a duty cycle (e.g., every 15 min to 4 h), stored on-board for the collar's life, uplinked in batches over Iridium SBD or GSM; vendors reduce fix rate when the animal is stationary (activity-sensor-gated schedules) and raise it in "virtual fence" zones; data are repaired by batch resend on next contact, never lost. — Unverified; medium confidence on specific scheduling features.
- [U] **Receiver-side filtering**: the Douglas Argos-Filter (Douglas et al. 2012, Methods in Ecology and Evolution) rejects fixes by maximum plausible speed and turning-angle/distance tests; **state-space models** (Jonsen, Flemming & Myers 2005, Ecology; `crawl`, `foieGras`/`aniMotum`) fuse irregular, class-labelled fixes into a continuous track with uncertainty. — Unverified; the papers are real.

### Inferences
- The tag practice "when you can't send everything, send a *summary statistic* of the blackout window" is a direct precedent for MinBand's blackout recovery: on reconnect, send current state plus a compact summary (e.g., number of entities appeared/disappeared, max displacement) rather than replaying deltas.
- Argos location classes are the ancestor of per-update confidence fields; the Douglas filter is the ancestor of receiver-side plausibility gating MinBand needs against spoofed or mis-detected entities.

### Gaps
- Exact Argos repetition-period limits and current message-size tables unverified.
- No verified numbers on how many fixes/day typical collars deliver vs attempt.

## 9. IoT (Sigfox, LoRaWAN, Iridium SBD; CBOR/protobuf/bit-packing)

### Takeaway
LPWAN and satellite IoT are the regime where per-message byte caps and legal duty cycles — not bits per second — are the budget: Sigfox 12-byte uplinks and 140 messages/day, LoRaWAN 1 % duty cycle in EU868 and 400 ms dwell limits elsewhere, Iridium SBD 340-byte messages. The design response is aggressive quantization (MAVLink's 42-byte `HIGH_LATENCY2` is a worked example), varints/CBOR for integers, and MAC-level commands that let the network widen a device's duty cycle.

### Cited Findings
- [V] **MAVLink `HIGH_LATENCY2` (message 235), "appropriate for high latency connections like Iridium"** — `pymavlink` 2.4.50, `dialects/v20/common.xml` (https://pypi.org/project/pymavlink/2.4.50/): packed struct format `<IiiHhhHHHBBBBBBBBBBBBbbbbbb` = **42 bytes** for a full vehicle status: latitude/longitude int32 in degE7, altitude int16 in m, **heading uint8 in deg/2**, **airspeed/groundspeed/windspeed uint8 in (m/s × 5)**, target distance uint16 in decametres, climb rate int8 in dm/s, `eph`/`epv` uint8 in dm as "maximum error … since last message", battery int8 %, 16-bit failure-flag bitmap, three custom int8 fields. It superseded `HIGH_LATENCY` (234) in 2020-10.
- [V] **MAVLink v2 framing conventions**: the payload has **trailing zero bytes truncated** ("MAVLink2 truncates trailing zero bytes from the payload", `pymavlink/mavutil.py`), and an optional **13-byte signature block** (`MAVLINK_SIGNATURE_BLOCK_LEN = 13`, `MAVLINK_IFLAG_SIGNED = 0x01`, `dialects/v20/common.py`). `ADSB_VEHICLE` (246) carries `tslc` = "time since last communication in seconds" (uint8) alongside each relayed ADS-B target — a staleness field in the message.
- [V] **LoRaWAN MAC commands (Scapy 2.8.0, `scapy/contrib/loraphy2wan.py`; https://pypi.org/project/scapy/2.8.0/)**: `DutyCycleReq` carries a 4-bit `MaxDCycle` (network-imposed aggregated duty cycle for the device); `TxParamSetupReq` carries `UplinkDwellTime`/`DownlinkDwellTime` ∈ {No limit, **400 ms**} and `MaxEIRP` ∈ {8, 10, 12, 13, 14, 16, 18, 20, 21, 24, 26, 27, 29, 30, 33, 36 dBm}; `LinkADRReq` carries data-rate/power/channel mask so the network can push a device to a faster rate.
- [U] **LoRaWAN Regional Parameters (RP002)**: EU863-870 — 1 % duty cycle on the default sub-band (0.1 % and 10 % sub-bands exist), max application payload **51 bytes at DR0–DR2 (SF12–SF10)**, 115 at DR3, **222 bytes at DR4–DR5 (SF8–SF7)**; a 51-byte SF12 frame takes ≈ 2.8 s on air, so 1 % allows ≈ 1 such frame every 4.7 min. **KR920-923**: no duty-cycle limit but **listen-before-talk** (carrier sense before each transmission) is mandatory, max EIRP 14 dBm (10 dBm on the lower channels), default channels 922.1/922.3/922.5 MHz. AS923 and US915 use 400 ms dwell-time limits, which cap DR0 payloads to 11 bytes. — Unverified; medium-high confidence on EU numbers, medium on KR920 details.
- [U] **Sigfox**: ultra-narrow-band 100 bit/s (EU), **12-byte max uplink payload**, **140 uplink messages/day**, **4 downlinks/day of 8 bytes**, each uplink sent 3 times on 3 random frequencies (~2 s each, ~6 s total), 1 % duty cycle derivation of the 140/day limit. — Unverified; high confidence.
- [U] **Iridium SBD**: mobile-originated message ≤ **340 bytes** (9602/9603 transceivers), mobile-terminated ≤ 270 bytes; latency seconds to ~1 min; ring alerts for MT; billed per message/per 50-byte increments by resellers (RockBLOCK). — Unverified; high confidence on 340/270.
- [V] **Protocol Buffers varints** exist as implemented (`google/protobuf/internal/wire_format.py`: `WIRETYPE_VARINT = 0`, `ZigZagEncode` "encodes signed integers so that they can be effectively used with varint encoding"; `encoder.py` `_VarintSize`), protobuf 7.36.2 (https://pypi.org/project/protobuf/7.36.2/). [U] Varints use 7 payload bits per byte (MSB = continuation), so values < 128 cost 1 byte and zig-zag maps −64..63 to 1 byte; CBOR (RFC 8949) encodes 0–23 in the initial byte, ≤ 255 in 2 bytes; MessagePack "positive fixint" 0–127 in 1 byte. `bitstruct` 8.23.0 ("like struct but working on bits") is the common Python tool for sub-byte packing (https://pypi.org/project/bitstruct/8.23.0/).

### Inferences
- `HIGH_LATENCY2` is the best worked example of *budget-driven quantization* found: heading at 2° and speeds at 0.2 m/s in 1 byte each, with `eph/epv` reporting the **worst** error since the last message — a precedent for MinBand reporting "max ghost error since last delta" as a one-byte integrity field.
- LoRaWAN's `MaxDCycle`/`LinkADRReq` are network-to-device budget commands — the same role as MinBand's budget controller, but driven from the receiver side; MinBand could accept an optional downlink "budget" command.
- Trailing-zero truncation is a free compression trick for sparse delta messages (zero = unchanged) that MinBand's packed deltas could reuse.

### Gaps
- Regional-parameter numbers (especially KR920) and Sigfox/Iridium limits unverified; LoRa Alliance, Sigfox and Iridium sites were blocked.

## 10. Perception and neuroscience (event cameras, predictive coding, event-triggered estimation, compressed sensing)

### Takeaway
An event camera pixel is MinBand's ghost at the pixel level: it stores the last transmitted log-intensity, fires only when the current value differs by a contrast threshold C (~10–15 %), and resets its reference on firing. Predictive coding in cortex and retina is the biological claim that only prediction errors propagate upward. The control-theory literature (event-triggered estimation) formalizes the key non-obvious result: **a non-update is information** — under a deterministic prediction-error trigger, silence tells the receiver the error is inside the threshold — but *only if silence cannot also mean loss*, which is exactly why heartbeats/keyframes are needed on lossy links.

### Cited Findings
- [V] **Event representation**: tooling for DVS data uses the structured event `(x: int16, y: int16, t: int64 [µs], p: bool)`; sensor resolutions DVS128 = 128×128, DAVIS346 = 346×260; timestamps are microseconds — `tonic` 1.7.0, `tonic/io.py`, `tonic/datasets/dvsgesture.py` (https://pypi.org/project/tonic/1.7.0/).
- [U] **Event-camera numbers** (Gallego et al., "Event-based Vision: A Survey", IEEE TPAMI 2020, arXiv:1904.08405 — blocked): a pixel emits an event when |log I(t) − log I(t_ref)| > C with C ≈ 10–15 % contrast (adjustable), then sets t_ref ← t; temporal resolution ~1 µs, latency tens of µs to ~1 ms, dynamic range ~120–140 dB (vs ~60 dB for frames), power ~10–30 mW; output rate is scene-dependent, from near zero for a static scene to > 10⁸ events/s (Prophesee Gen4 up to ~10⁹ events/s), so **data reduction is large on average but unbounded in the worst case**; commercial sensors therefore include **event-rate controllers that drop events under a bandwidth cap**. — Unverified; high confidence on the mechanism and dB figures.
- [U] **Predictive coding**: Rao & Ballard, "Predictive coding in the visual cortex" (Nature Neuroscience 1999) — hierarchical model where feedback carries predictions and feedforward carries **residual errors**, explaining extra-classical receptive-field effects; Hosoya, Baccus & Meister, "Dynamic predictive coding by the retina" (Nature 2005) — retinal ganglion cells adapt to signal deviations from recent statistics; Koch et al., "How much the eye tells the brain" (Current Biology 2006) estimated guinea-pig retinal output ≈ 875 kbit/s and extrapolated human ≈ 10 Mbit/s — i.e. the optic nerve is itself a heavily compressed, change-emphasizing channel. — Unverified; papers are real.
- [U] **Event-triggered state estimation**: Miskowicz, "Send-on-delta concept" (Sensors 2006) formalizes deadband sampling; Trimpe & D'Andrea, "Event-Based State Estimation With Variance-Based Triggering" (IEEE TAC 2014) — the sender **simulates the receiver's estimator** and transmits when the receiver's error variance would exceed a bound (the ghost pattern, with variance instead of position error); Wu, Jia, Johansson & Shi, "Event-Based Sensor Data Scheduling: Trade-off Between Communication Rate and Estimation Quality" (IEEE TAC 2013) — with a deterministic innovation threshold, the receiver's MMSE estimate **improves on non-transmission instants** (the posterior is a truncated Gaussian, approximated as Gaussian), giving a closed-form rate-vs-error trade-off; Sijs & Lazar (IEEE TAC 2012) and later work handle **packet loss**, where silence becomes ambiguous and periodic "time-synchronous" updates are added. — Unverified; the papers are real and the "silence is information" result is the central one.
- [U] **Compressed sensing** (Candès, Romberg & Tao 2006; Donoho 2006): a k-sparse signal in N dimensions is recoverable from O(k·log(N/k)) random linear measurements; the Rice single-pixel camera (Duarte et al. 2008) is the hardware demonstration. The parallel to MinBand is only qualitative: bytes scale with the *number of surprises* (sparsity of the prediction error), not with the scene size. — Unverified.

### Inferences
- Event cameras are the quantified warning for MinBand's budget: a change-triggered sender has **no upper bound on rate** under high dynamics (many entities manoeuvring at once); the hardware answer was a rate controller that drops, i.e. MinBand's threshold-widening controller is necessary, not optional.
- Wu et al./Trimpe give MinBand a free accuracy gain: when the link is known-good, the twin can tighten its uncertainty on every tick without a message, because the edge's deterministic trigger guarantees the error is within threshold. Under loss this is unsafe — hence keyframes are not only repair but the mechanism that keeps "silence = within threshold" trustworthy.
- Variance-based triggering suggests triggering on *uncertainty growth* (e.g., time since last confirmed detection) as well as position error.

### Gaps
- All numerical event-camera figures and the exact theorem statements are from memory; arXiv/IEEE were blocked.

## 11. Finance and media (market-data conflation, video codecs, adaptive bitrate)

### Takeaway
Market-data distribution and video codecs independently converged on MinBand's rules: **conflation** (replace queued updates for the same key with the newest, never backlog), **deltas against a shared previous message with presence bits** (FIX/FAST), **snapshot channels separate from incremental channels** for resync after a gap, P/B-frames with 1-bit "skip" blocks for unchanged regions, **periodic keyframes to bound error propagation**, and **receiver-requested keyframes** (PLI/FIR) rather than retransmission over long RTTs. Adaptive bitrate is the budget controller.

### Cited Findings
- [U] **Conflation**: market-data platforms (Refinitiv RTDS/TREP, Bloomberg B-PIPE, Solace, Kx) offer "conflated" delivery for slow consumers: within each interval (configurable, typically 100 ms–1 s) or when the consumer's queue is full, multiple updates for the same instrument are merged so only the **latest state** (plus aggregated fields like volume) is sent; count-based and time-based conflation are both standard. — Unverified; high confidence on the concept.
- [U] **CME MDP 3.0**: an **incremental** UDP multicast feed with per-channel sequence numbers plus separate **snapshot/recovery** multicast channels (and an instrument-definition channel); on a detected gap the consumer resynchronizes from the snapshot channel (or a TCP replay for short gaps) — gap repair by *state*, not by retransmission of each lost packet. — Unverified; high confidence.
- [U] **FIX/FAST (FIX Adapted for STreaming)**: fields are encoded with a **presence map** (one bit per field) and per-field operators `constant`, `default`, `copy` (same as previous message), `delta` (send difference from previous value), `increment` (sequence numbers), so an unchanged field costs 1 bit and a slightly changed price costs a 1-byte delta; integers are stop-bit varints (7 bits/byte). This is the exchange-industry twin of Quake/Tribes dirty bits. — Unverified; high confidence.
- [U] **Video codecs**: H.264/AVC P- and B-frames predict from references and code only the residual; a **P_Skip / B_Skip macroblock** (signalled via `mb_skip_run`/`mb_skip_flag`) sends *no* data and tells the decoder "copy from the reference at the predicted motion vector" — the macroblock-level "ghost is right"; x264 defaults bound error propagation with a keyframe at most every **250 frames** (`keyint`) and at least every 25 (`min-keyint`), with scene-cut detection (`scenecut 40`) forcing earlier I-frames; **periodic intra refresh** spreads the keyframe cost across frames to avoid bitrate spikes. Packet loss in a P-chain causes drift until the next I-frame. — Unverified; high confidence on x264 defaults.
- [U] **Real-time transport repair**: RTP/AVPF (RFC 4585) **Picture Loss Indication (PLI)** and RFC 5104 **Full Intra Request (FIR)** let the receiver ask for a new keyframe rather than retransmission; RFC 4588 RTX retransmission is used only when RTT is short; WebRTC implementations rate-limit keyframe requests because synchronized FIR storms from many receivers caused bitrate spikes ("I-frame storms" in IPTV multicast). — Unverified; high confidence.
- [U] **MPEG-DASH / HLS ABR**: media is cut into 2–10 s segments offered at a bitrate ladder; the client picks a representation per segment from throughput estimates and buffer level (BOLA, MPC, Pensieve); switching is only at segment boundaries, which bounds oscillation. — Unverified; high confidence.

### Inferences
- "Snapshot channel + incremental channel + sequence numbers" (CME) is the production pattern MinBand's "keyframe every 2 s + deltas" implements in one stream; FAST's presence map is the byte-level encoding MinBand's packed deltas should resemble.
- PLI/FIR is a strong precedent for a tiny MinBand back channel: a 1-byte "send me a keyframe for entity set X" beats any retransmission queue when loss is bursty.
- Skip-macroblocks are the proof that "no bytes for a correct prediction" scales to millions of elements per second inside a codec — MinBand's per-entity skip is the same idea at coarser granularity.

### Gaps
- No primary standard text verified; conflation interval numbers vary by vendor.

## 12. Older military practice (WWII reporting, artillery call-for-fire, brevity codes)

### Takeaway
Pre-digital militaries already sent "only what changed" against a shared reference: artillery corrections are deltas from the last burst, "shift from a known point" encodes position relative to a shared datum, the Dowding system's filter room de-duplicated many observer reports into one track and displayed plot age by colour, and U-boat "Kurzsignale" compressed reports to a few letters. Their failure modes — ambiguous references, action-word homonyms, stereotyped formats enabling cryptanalysis — are the historical versions of MinBand's integrity risks.

### Cited Findings
- [U] **Artillery call for fire (US FM 6-30 / ATP 3-09.30)**: three transmissions — (1) observer identification + warning order ("fire mission"), (2) **target location** (grid, polar, or **shift from a known point**: a delta from a pre-registered reference), (3) target description, method of engagement, method of fire and control; **adjustments are pure deltas from the last observed burst** ("left 50, add 100"); "REPEAT" means fire the same data again (a resend), which is why "SAY AGAIN" is used for "please retransmit" — an explicit guard against a dangerous homonym. — Unverified; high confidence.
- [U] **WWII Dowding system (RAF Fighter Command)**: radar (Chain Home) and Royal Observer Corps plots were telephoned to a **Filter Room** that merged duplicate reports of the same raid into a single track with a raid number, estimated strength and height, before passing it to operations rooms; plotting tables used counters whose colour matched a **sector clock** divided into 5-minute red/yellow/blue segments, so the age of every plot was visible at a glance and plots older than two colour segments were cleared — a staleness display convention. — Unverified; high confidence.
- [U] **Kriegsmarine Kurzsignale (short-signal) and weather short-signal books**: U-boat position/weather/contact reports were encoded into a few letter groups before Enigma encryption to minimize airtime against Allied HF-DF; the stereotyped formats (especially weather reports) gave Bletchley Park cribs (known plaintext) that helped break naval Enigma. — Unverified; high confidence.
- [U] **Brevity codes** (NATO APP-7, US Multi-Service Brevity Codes ATP 1-02.1): fixed vocabulary with one meaning per word ("BOGEY", "BANDIT", "BINGO", "FOX TWO"), designed so a single word conveys a full state change; the standards explicitly warn against local variants because a mis-decoded brevity word is worse than a long plain message. — Unverified.

### Inferences
- "Shift from a known point" + "add/left" corrections is dead reckoning by voice: both ends share a reference (the ghost), only the error is sent. The REPEAT/SAY AGAIN rule is the lesson that a *resend* command must be unambiguous from a *data* command — relevant to MinBand's keyframe-vs-delta message typing.
- The filter room is the historical R2/correlation function (§5) and the sector clock is the historical ASTERIX "coasted" bit (§4): age must be visible on the picture.
- Kurzsignale show the integrity cost of extreme compression with fixed formats: predictable structure is a gift to an adversary; MinBand's packed deltas should assume the same if the link is ever observed.

### Gaps
- Could not verify the sector-clock clearing rule's exact wording or the call-for-fire manual numbering.

## 13. Cross-domain failure modes and the fixes adopted (synthesis)

### Takeaway
Across all domains the same five failures recur, and the fixes are consistent enough to read as rules.

### Cited Findings (each item points back to the verified or flagged findings above)
- **False confidence from smooth extrapolation** → cap extrapolation and show age: Source engine 0.25 s extrapolation cap [U §1]; ASTERIX CST "coasted" bit and per-sensor track ages in 0.25 s units [U §4]; ADS-B decoder 30 s reference window / 300 s eviction [V §4]; AIS "62 = dead-reckoned" timestamp sentinel [U §3]; sector-clock plot colours [U §12]; MAVLink `tslc` seconds-since-last-communication field [V §9].
- **Loss on lossy links** → repair by state, not by replaying packets: Tribes re-dirtying + Quake/Source delta-from-last-ack with full-snapshot fallback [U §1]; GOOSE stNum/sqNum repetition of full state [U §7]; DNP3 integrity poll + overflow IIN bit [U/V §7]; CME snapshot channel [U §11]; RTP PLI/FIR keyframe requests [U §11]; DTN lifetime expiry and BPv7 dropping custody transfer [U/V §6].
- **Congestion collapse of change-triggered senders** → explicit budget controllers: ETSI DCC CBR states and LIMERIC target CBR 0.68 [U §2]; SAE J2945/1 ITT 100–600 ms by density [U §2]; event-camera rate controllers [U §10]; LoRaWAN `MaxDCycle`/duty cycles [V/U §9]; AIS self-organized slot reservation and "received stations" load count [V §3]; x264 periodic intra refresh to avoid keyframe spikes and FIR rate-limiting [U §11].
- **Correction popping / flapping** → hysteresis and smoothing: ETSI `N_GenCam = 3` hold rule [U §2]; Link 16 TQ margin before R2 shift [U §5]; game smoothing-with-snap-threshold [U §1]; GOOSE geometric back-off [U §7].
- **Spoofing / ghost tracks on unauthenticated broadcasts** → plausibility + multi-sensor confirmation, and (where format allows) signatures: AIS SDR spoofing (Balduzzi 2014) and GPS spoofing incidents, Douglas-style speed/turn filters [U §3, §8]; ADS-B ghost injection and MLAT/radar cross-checks, claimed NIC/NACp/SIL ≠ authenticity [V/U §4]; ASTERIX GHO ghost-track bit [U §4]; V2X accepting 70–220 bytes of signature/certificate per 200-byte CAM [U §2]; MAVLink optional 13-byte signature [V §9].
- **Many sensors, one target** → one reporter per track with quality-based election and per-reporter ID namespaces: Link 16 R2/TQ/track-number blocks [U §5]; Dowding filter room [U §12]; ADS-B decoder phantom rejection with recoverable history [V §4].

### Inferences
- The strongest "they solved it decades ago" items for MinBand: Tribes ghost manager (1999–2001), DNP3 integrity poll + overflow flag, GOOSE stNum/sqNum geometric repetition, Link 16 R2/TQ, CPR's explicit receiver-state validity windows, and the event-triggered-estimation theorem that silence carries information only when loss is excluded.
- The reverse direction (drone work ahead of these fields): none of the above domains combines *perceived, non-owned* entities with confidence-weighted deltas; the closest are tactical data links (tracks with TQ) and animal tags (fixes with location class), neither of which runs the receiver's predictor on the sender.

### Gaps
- Because no standard text or paper could be fetched this session, every [U] item above needs a verification pass against the named document before it is quoted in the report. The [V] items can be quoted as "as implemented in <package> <version>".
